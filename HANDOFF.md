# Collapse: точка продолжения разработки

Исходники опубликованы в двух GitHub-репозиториях: клиент и backend.
Публикация включает текущие рабочие исходники; подготовка к публикации не меняет
поведение приложения. Последняя функциональная поставка — 22 сентября 2026:
медиаатлас, просмотрщик, reply/forward и компоновка медиапузырьков.
История фактических проверок, включая проверку push от 12 октября, — в `VERIFICATION.md`.

## С чего начать на другом ПК

1. Клонировать оба репозитория соседними папками (команды ниже).
2. Читать `AGENTS.md` каждого проекта, который будете менять; проверить Git status.
3. Следовать `START_HERE.md` в клиенте: установить закреплённый Flutter, подготовить чистый
   backend, установить зависимости клиента и его локального пакета, собрать web.
4. Создать новые тестовые аккаунты. Старые аккаунты, сессии, SQLite/PostgreSQL,
   медиафайлы пользователей, ключи подписи и секреты намеренно не переносятся.

```sh
git clone https://github.com/Z3R0F0/collapse-backend.git
git clone https://github.com/Z3R0F0/collapse-client.git
```

Версию каждого проекта задаёт его Git-коммит. Для работы с GitHub-копиями
не нужны файлы контрольных сумм или метаданных прежнего ZIP-снимка.

## Что уже реализовано

- Обычный Tinode-мессенджер без прежнего бренда, ботов, сценариев и игрового кода.
  Авторизация, профиль, контакты, личные/групповые чаты; Android, iPhone и web.
  iPad и отдельные native desktop targets не включены.
- GetIt -> Cubit -> repository -> локальный `packages/tinode` / Drift. Одна
  account/server-scoped база; durable outbox и байты вложений переживают рестарт.
- Двунаправленная история: страницы по 40, окно до 120 сообщений, независимые
  coverage/cursors, API-запросы, окно, viewport и анимации. Latest/reply/search
  открывают готовый снимок, а не прокручивают промежуточные страницы.
- Канонические URL и адаптивный desktop/mobile facade с сохранением одного
  ChatCubit, черновика и позиции. Скрытые панели не читают сообщения и не играют
  медиа. Терминальный light/dark UI, EN/RU, Drafty/Markdown и spoilers.
- Footer сообщения размещается по реальной геометрии отформатированного текста.
  Reply/forward компактны; размеры медиа задают геометрию пузырька.
- Отдельный атлас фото/видео, аудио и файлов в профиле чата. PostgreSQL-indexed
  `get.what=media` / `meta.media` не затрагивают историю, receipts или ChatCubit.
  Drift schema 3 кеширует метаданные; ACK сохраняет идентичность вложения.
- Hero-просмотрщик: мобильные zoom/carousel/dismiss, desktop клавиши/кнопки,
  сохранение, пауза при скрытии. Жесты принадлежат `extended_image`.

## Что нельзя незаметно потерять

Не объединять outbox, состояние окна, скролл и анимации. Не загружать всю историю
ради медиа. Не переименовывать Drafty entity keys и не присылать обычные `data`
пакеты в ответ на media query. Не пересоздавать router/Cubit при resize. Не
подменять unread количеством скрытых или новых относительно окна сообщений.
Сохранять проверки account/session generation, transactional ACK merge,
top-level `extra.attachments` и distinction blocked/exhausted offline edges.

Backend — поддерживаемый репозиторий с небольшим overlay поверх закреплённого
Tinode v0.25.3. Исходник upstream, SDK и внешние зависимости скачиваются при setup
с проверками версии/хеша. Репозитории не являются полностью офлайн-окружением.

## Проверено и что осталось

**Проверка переноса 25 сентября:** ZIP независимо распакован в чистую папку.
Зависимости клиента и локального пакета установлены с `--enforce-lockfile`
(из локального pub-cache); `flutter analyze` и `dart analyze` — без замечаний.
`flutter test --no-pub --concurrency=2` — **543 PASS, 1 opt-in skip**;
`dart test` в `packages/tinode` — **106 PASS**. Проверены синтаксис backend-скриптов,
контрольные суммы, соответствие исходным рабочим файлам, исполняемые права,
отсутствие приватных путей/текущих секретов и повторная упаковка после двух
`git init` без коммитов. После тестов обновлена только документация handoff.
Бэкенд, браузер и native-сборки при этой упаковке заново не запускались;
новое скачивание зависимостей без кеша не проверялось. Работающие сервисы
и существующие пользовательские данные не менялись.

Последняя функциональная проверка: общий Flutter-прогон **538 PASS, 1 opt-in
skip**; после финальной узкой MIME/unknown-duration правки — **39 PASS** целевых
тестов и чистый полный анализатор. Tinode Dart package — **106 PASS**; live-server
integration/regression — **15 PASS**. Сервер: Go tests и отдельные PostgreSQL/Tinode
ACL/cursor/deletion/migration проверки прошли. Это исторические результаты,
не обещание проверки на новом ПК; повторите подходящие команды после установки.

В Chrome проверены независимый атлас из 34 вложений, категории, воспроизведение,
пять первых zoom/reset, мобильные touch-жесты, кеш офлайн, сохранение черновика и
геометрии, прямой media URL. Ложный первый zoom-reset был вызван режимом снятия
обрезанного скриншота (`captureBeyondViewport:true`); production click/focus
workaround не добавляли.

WebM: исправление ошибочного `audio/weba` из MIME-библиотеки и отрицательной
неизвестной длительности включено и покрыто тестами. **Повторная браузерная
приёмка WebM отложена по просьбе владельца**, чтобы не задерживать выпуск.
Не считать её пройденной и не превращать автоматически в блокирующую задачу.

Физические iOS/Android и Docker runtime для последнего этапа не проверены.
Нативный push требует собственных Firebase/APNs/FCM настроек и выключен по
умолчанию; web push и rich-avatar push не реализованы. Native OS deep-link
associations и подпись магазина настраиваются отдельно. Нет E2EE; Tinode publish
не гарантирует exactly-once при потере ACK. Offline означает уже сохранённые
данные, а не доступ к никогда не скачанным оригиналам.

## Следующий рабочий шаг

Сначала восстановить окружение по START_HERE и прогнать анализатор/тесты из
копии. Затем продолжать конкретную новую задачу, сохраняя описанные границы.
Для повторной упаковки из двух Git-репозиториев: из клиента
`node tool/package_sources.mjs /absolute/path/new-snapshot.zip`.
Не перезаписывать старые архивы и не включать сгенерированные секреты/базы.
